# DueDaily — ระบบแจ้งเตือนงานประจำวัน (เวอร์ชันมีเซิร์ฟเวอร์ + Push Notification จริง)

เวอร์ชันนี้ต่างจากเวอร์ชันเดิม (localStorage-only) ตรงที่ **มีเซิร์ฟเวอร์ขนาดเล็ก (Node.js + Express)** คอยเก็บข้อมูลงาน
และคอยตรวจสอบวันครบกำหนดเบื้องหลัง แล้วส่ง **push notification จริงไปที่โทรศัพท์ได้แม้ปิดแอป/ปิดหน้าเว็บอยู่**
(รองรับ iPhone ตั้งแต่ iOS 16.4 ขึ้นไป ผ่านการ "เพิ่มไปยังหน้าจอโฮม")

## สิ่งที่เปลี่ยนไปจากเวอร์ชันเดิม (สำคัญ ควรอ่านก่อนใช้งาน)

- **ข้อมูลงานย้ายจาก localStorage ในเบราว์เซอร์ ไปเก็บบนเซิร์ฟเวอร์แทน** (ไฟล์ `data/tasks.json`) เพราะการจะส่งแจ้งเตือนตอนแอปปิดอยู่ได้ ต้องมีโปรแกรมที่ทำงานอยู่ตลอดเวลาคอยตรวจว่างานใกล้/เลยกำหนดหรือยัง ซึ่งเบราว์เซอร์ที่ปิดอยู่ทำแบบนั้นไม่ได้
- **ไม่มีระบบล็อกอิน/รหัสผ่าน** — ออกแบบมาสำหรับ "ใช้คนเดียว" ตามที่แจ้งไว้ตอนแรก ถ้านำไปฝากบนโฮสต์ที่มี URL สาธารณะ ใครก็ตามที่รู้ URL จะเห็น/แก้ไขข้อมูลงานได้ทั้งหมด **ควรเลือกโฮสต์ที่ตั้งรหัสผ่านการเข้าถึงได้ (Basic Auth) หรืออย่างน้อยใช้ URL ที่เดายาก ถ้ากังวลเรื่องความเป็นส่วนตัว**
- ชื่อผู้ใช้/ชื่อระบบ (โปรไฟล์) ยังคงเก็บใน localStorage เหมือนเดิม (เป็นแค่ความชอบส่วนตัวต่อเครื่อง ไม่จำเป็นต้องอยู่บนเซิร์ฟเวอร์)

## โครงสร้างไฟล์

```
duedaily-server/
├── server.js              จุดเริ่มเซิร์ฟเวอร์ Express + API ทั้งหมด
├── package.json
├── lib/
│   ├── taskLogic.js        คำนวณสถานะงาน/ตัดสินใจว่าต้องแจ้งเตือนหรือยัง (ไม่พึ่ง library ภายนอก)
│   ├── store.js             อ่าน/เขียนไฟล์ data/*.json
│   ├── seed.js               ข้อมูลตัวอย่างที่ใส่ให้ตอนรันครั้งแรก
│   └── push.js                ห่อ web-push (VAPID keys + ส่งแจ้งเตือน)
├── public/                 หน้าเว็บ (frontend) — เดิมเป็น localStorage version ตอนนี้คุยกับ API แทน
│   ├── index.html
│   ├── css/style.css
│   ├── js/app.js
│   ├── manifest.webmanifest
│   ├── sw.js                Service worker (รับ push, จัดการคลิกที่การแจ้งเตือน)
│   └── icons/icon-192.png, icon-512.png
└── data/                    สร้างอัตโนมัติตอนรันครั้งแรก (tasks.json, subscriptions.json, vapid.json)
```

## วิธีรันบนเครื่องตัวเอง (ทดสอบก่อนขึ้นโฮสต์จริง)

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 18 ขึ้นไป

```bash
cd duedaily-server
npm install
npm start
```

แล้วเปิด `http://localhost:3000`

> **หมายเหตุสำคัญเกี่ยวกับการทดสอบโค้ดนี้**: โค้ดชุดนี้เขียนและตรวจสอบไวยากรณ์ (syntax) เรียบร้อยแล้ว ตรรกะหลักทั้งหมด (การคำนวณสถานะงาน ปกติ/ใกล้ถึงกำหนด/เลยกำหนด, การตัดสินใจว่าเมื่อไหร่ควรแจ้งเตือน, การบันทึก/อ่านไฟล์ข้อมูล) ผ่านการทดสอบอัตโนมัติแล้วจริง และหน้าเว็บทั้งหมด (เพิ่ม/แก้ไข/ลบงาน, ปฏิทิน, ไทม์ไลน์, ตารางงานทั้งหมด, แก้ไขโปรไฟล์) ได้ทดสอบต่อกับเซิร์ฟเวอร์จำลองที่ใช้ตรรกะชุดเดียวกันแล้วว่าทำงานถูกต้องและไม่มี error
>
> แต่ส่วนที่ **ยังไม่สามารถทดสอบการรันจริงได้ในสภาพแวดล้อมที่ใช้พัฒนา** คือตัว `npm install` และการรัน Express/web-push จริง เนื่องจากเครื่องมือพัฒนาที่ใช้สร้างไฟล์เหล่านี้ไม่มีสิทธิ์เข้าถึงอินเทอร์เน็ตสำหรับดาวน์โหลด package (ถูกบล็อกโดยนโยบายของสภาพแวดล้อมนั้น) จึงรัน `npm install` ไม่ได้จริงในขั้นตอนพัฒนา — โค้ดใน `server.js` และ `lib/push.js` เขียนตาม API มาตรฐานของ `express` และ `web-push` (v3) ที่มีเอกสารชัดเจนและเสถียร แต่ **แนะนำให้รัน `npm install && npm start` แล้วลองทดสอบเบื้องต้นบนเครื่องของคุณเองก่อนใช้งานจริงหรือก่อนขึ้นโฮสต์**เพื่อความมั่นใจ ถ้าเจอปัญหาแจ้งกลับมาได้ จะช่วยแก้ไขให้

## การนำขึ้นโฮสต์ (Deploy) เพื่อให้ใช้งานได้จริงบนมือถือ

Push notification (โดยเฉพาะบน iOS) **ต้องใช้ HTTPS เสมอ** (ยกเว้น `localhost` ตอนทดสอบ) จึงต้องขึ้นโฮสต์ที่มี HTTPS ให้ ไม่สามารถเปิดจากไฟล์ในเครื่องได้เหมือนเวอร์ชันก่อน

ตัวเลือกโฮสต์ฟรี/ราคาถูกที่รองรับ Node.js เช่น Render, Railway, Fly.io, Glitch หรือ VPS ส่วนตัว ขั้นตอนคร่าวๆ:

1. อัปโหลดทั้งโฟลเดอร์ `duedaily-server` ขึ้น Git repository (GitHub เป็นต้น)
2. เชื่อม repository เข้ากับบริการโฮสต์ ตั้งค่า Build Command เป็น `npm install` และ Start Command เป็น `npm start`
3. ตั้งค่า Persistent Disk / Volume ให้ครอบคลุมโฟลเดอร์ `data/` ถ้าโฮสต์รองรับ (ไม่งั้นข้อมูลจะหายเมื่อ redeploy) — ถ้าโฮสต์ไม่รองรับ persistent disk ในแผนฟรี ให้พิจารณาย้าย `data/tasks.json` ไปเก็บใน volume ที่ติดมากับแผนนั้นๆ
4. (แนะนำ) ตั้งค่า **External Cron / Uptime pinger** ให้เรียก `GET https://<โดเมนของคุณ>/api/run-check` ทุกๆ 5–15 นาที เพราะโฮสต์ฟรีหลายเจ้าจะ "หลับ" เซิร์ฟเวอร์เมื่อไม่มีคนเข้าใช้ ทำให้ `setInterval` ภายในโค้ดไม่ทำงานตามเวลาจริง การมี pinger ภายนอกช่วยให้ระบบตรวจสอบงานสม่ำเสมอแม้เซิร์ฟเวอร์จะหลับไปพักหนึ่ง (ใช้บริการฟรีอย่าง cron-job.org, UptimeRobot, GitHub Actions scheduled workflow ก็ได้)
5. เปิด `https://<โดเมนของคุณ>` แล้วเข้าสู่ขั้นตอนเปิดการแจ้งเตือนด้านล่าง

## วิธีเปิดการแจ้งเตือนบน iPhone (iOS 16.4 ขึ้นไป)

1. เปิดเว็บนี้ด้วย **Safari เท่านั้น** (Chrome/เบราว์เซอร์อื่นบน iOS ใช้ Web Push ไม่ได้ เพราะ Apple อนุญาตเฉพาะ Safari)
2. แตะปุ่มแชร์ (ไอคอนสี่เหลี่ยมมีลูกศรชี้ขึ้น) ด้านล่างจอ แล้วเลือก **"เพิ่มไปยังหน้าจอโฮม" (Add to Home Screen)**
3. เปิดแอปจาก **ไอคอนที่เพิ่งเพิ่มบนหน้าจอโฮม** (ต้องเปิดจากไอคอนนี้ ไม่ใช่จาก Safari โดยตรง iOS ถึงจะอนุญาตให้ขอสิทธิ์แจ้งเตือนได้)
4. ในแอป กดเมนู **"แจ้งเตือนบนมือถือ"** ด้านซ้าย แล้วกด **"เปิดการแจ้งเตือน"**
5. iOS จะถามสิทธิ์แจ้งเตือน กด "อนุญาต" — เสร็จแล้วสามารถกด "ส่งการแจ้งเตือนทดสอบ" เพื่อลองดูว่าได้รับแจ้งเตือนจริงไหม

ถ้าลืมขั้นตอน "เพิ่มไปยังหน้าจอโฮม" แล้วกดเปิดการแจ้งเตือนจากแท็บ Safari ปกติ แอปจะแจ้งเตือนให้ทำตามขั้นตอนนี้ก่อน (ไม่ error แต่จะไม่ขอสิทธิ์ให้ เพราะ iOS บล็อกไว้)

Android (Chrome) และเดสก์ท็อป (Chrome/Edge/Firefox) เปิดใช้งานได้ทันทีโดยไม่ต้อง "เพิ่มไปยังหน้าจอโฮม" ก่อน กดเมนู "แจ้งเตือนบนมือถือ" แล้วกด "เปิดการแจ้งเตือน" ได้เลย

## ฟีเจอร์

ฟีเจอร์เดิมทั้งหมดจากเวอร์ชัน localStorage ยังอยู่ครบ (เพิ่ม/แก้ไข/ลบงาน, คำนวณสถานะอัตโนมัติ, แดชบอร์ดสรุป, ปฏิทิน, ไทม์ไลน์, กระดิ่งแจ้งเตือนในหน้าเว็บ, ค้นหา/กรอง, หน้ารายการงานทั้งหมด, ส่งออก/นำเข้าข้อมูล, แก้ไขชื่อผู้ใช้/ชื่อระบบในแอป) บวกเพิ่มเติม:

- **Push notification จริงไปยังหน้าจอโฮมของโทรศัพท์** แม้ปิดแอป/ปิดเบราว์เซอร์อยู่ — แจ้งเตือนอัตโนมัติเมื่องานเข้าสู่สถานะ "ใกล้ถึงกำหนด" (ภายใน 48 ชม.) หรือ "เลยกำหนด"
- ปุ่ม **"ส่งการแจ้งเตือนทดสอบ"** เพื่อเช็คว่าตั้งค่าถูกต้อง
- ระบบตรวจสอบเบื้องหลังทำงานทุก 5 นาที (`setInterval`) และมี endpoint `/api/run-check` ให้เรียกจาก cron ภายนอกได้ เพื่อความน่าเชื่อถือบนโฮสต์ฟรีที่ "หลับ" เซิร์ฟเวอร์เป็นระยะ
- แต่ละงานจะแจ้งเตือน "ใกล้ถึงกำหนด" ครั้งเดียว และ "เลยกำหนด" อีกครั้งเดียว (ไม่สแปมซ้ำ) — ถ้าแก้ไขวันครบกำหนดใหม่ ระบบจะรีเซ็ตให้แจ้งเตือนใหม่ได้อีกครั้งตามกำหนดใหม่

## การปรับแต่งเพิ่มเติม

- **เกณฑ์ "ใกล้ถึงกำหนด"**: แก้ค่า `NEAR_HOURS` ใน `lib/taskLogic.js` (ค่าเริ่มต้น 48 ชั่วโมง) — ต้องแก้ทั้งใน `lib/taskLogic.js` (ฝั่งเซิร์ฟเวอร์) และ `public/js/app.js` (ฝั่งหน้าเว็บ ใช้ตัวแปรชื่อเดียวกัน) ให้ตรงกัน
- **ความถี่การตรวจสอบเบื้องหลัง**: แก้ค่า `CHECK_INTERVAL_MS` ใน `server.js`
- **สีสัน**: ปรับตัวแปรในบล็อก `:root{...}` บนสุดของ `public/css/style.css`
- **ชื่อผู้ใช้ / ชื่อระบบ**: คลิกวงกลมอวตาร์มุมขวาบนในแอปเพื่อแก้ไขได้เลย ไม่ต้องแก้โค้ด
- **ไอคอนแอป**: แทนที่ไฟล์ `public/icons/icon-192.png` และ `icon-512.png` ด้วยไอคอนของคุณเอง (ขนาดเท่าเดิม)

## ไฟล์ที่ไม่ได้รวมมาด้วย (ใช้ตอนพัฒนาเท่านั้น)

ระหว่างพัฒนามีการสร้างไฟล์ `dev-mock-server.js`, `dev-playwright-test.js`, และ `lib/taskLogic.selftest.js` ไว้ทดสอบโค้ดโดยไม่ต้องพึ่ง `npm install` (เพราะสภาพแวดล้อมตอนพัฒนาเข้าอินเทอร์เน็ตไม่ได้) ไฟล์เหล่านี้ **ไม่จำเป็นสำหรับการใช้งานจริงและไม่ได้รวมมาในชุดที่ส่งมอบ** — ถ้าต้องการดูว่าตรรกะถูกทดสอบอย่างไรสามารถขอเพิ่มเติมได้

## ข้อจำกัดที่ควรทราบ

- เป็นแอปสำหรับ **ผู้ใช้คนเดียว** ไม่มีระบบล็อกอิน — ทุกคนที่รู้ URL เข้าถึงข้อมูลได้ทั้งหมด (ดูหัวข้อ "สิ่งที่เปลี่ยนไป" ด้านบน)
- Push notification ต้องใช้ HTTPS เสมอ (ไม่นับ localhost) จึงต้องขึ้นโฮสต์จริงก่อนถึงจะทดสอบการแจ้งเตือนบนมือถือได้
- บน iOS ต้อง "เพิ่มไปยังหน้าจอโฮม" ผ่าน Safari ก่อนเสมอ ไม่สามารถขอสิทธิ์แจ้งเตือนจากแท็บ Safari ปกติได้ (ข้อจำกัดจาก Apple ไม่ใช่จากแอปนี้)
- โฮสต์ฟรีบางเจ้าจะ "หลับ" เซิร์ฟเวอร์เมื่อไม่มีคนเข้าใช้งานนาน — แนะนำให้ตั้ง external cron ping ตามหัวข้อ Deploy ด้านบน เพื่อให้ตรวจสอบวันครบกำหนดได้สม่ำเสมอ
